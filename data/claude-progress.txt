Architectural trade-offs
- Per-phase checkpoint files instead of a single blob: each phase
  transition is one small atomic write, and a corruption in one
  phase's checkpoint doesn't taint the others. Cost: the runner
  has to keep two persistence surfaces in sync (the main
  `draft_state.json` plus the per-phase file). They serve
  different needs (the main file is the source of truth for the
  in-memory `DraftContext`; the per-phase file is the resume
  contract), so we keep both.
- Event bus as a per-project singleton, not a global channel:
  matches the per-project scope of `DraftContext`. Cost: bus
  state lives for the lifetime of the process; tests must call
  `progress.reset_all()` to start clean (not currently needed in
  the test suite, but documented in the module).
- Drop-on-full subscriber queues (not back-pressure): SSE
  subscribers can be slow (browser throttling, paused tab). We'd
  rather drop a phase-progress event for a slow client than have
  the LLM wait on a queue. The terminal `done` event is
  guaranteed because it's published on `run_all`'s `finally`,
  after the phases have completed, so it always arrives.
- Synchronous `_get_event_loop` helper was removed from the
  runner: the runner only uses `await self.event_bus.publish(...)`,
  so there's no sync publish path. Simpler code, slightly more
  `async` surface area.
- The SSE endpoint is purely passive: it does not run a phase
  itself. Clients subscribe *before* kicking off the work, and
  receive every event the runner publishes. This matches
  opendraft's `/draft/.../stream` model and keeps the
  subscription cancellable from the client side (just close the
  connection).
